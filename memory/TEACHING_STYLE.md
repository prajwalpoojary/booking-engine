# Teaching Style Preference

User prefers guided discovery approach:
1. Start with diagnostic questions to assess current understanding
2. Push on partial answers to identify exact gaps
3. Teach from what they already know (use their booking engine examples)
4. Give small, focused exercises (not full features)
5. Review like a PR with scorecard (what's right, what's wrong, production implications)
6. Follow-up question to confirm understanding before moving on
7. Never build entire feature for them - scaffold and guide but let them write code

Key principles:
- Precision under follow-up (answer the exact question asked)
- Not stopping halfway in reasoning (complete the thought)
- Performance thinking beyond surface level
- Component architecture: shared vs local state, lifting state to common ancestor
- Custom hooks eliminate duplication
- Context API for rare-changing shared data, not high-frequency updates
